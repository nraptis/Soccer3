WindowRotationPack migration and retired-cipher cleanup — 2026-11-03

IMPLEMENTATION
The active composer now farms and consumes WindowRotationPack directly.
Eighteen jobs supply 128 sampling windows and 16 masked byte rotations.
Each job receives a separate 48 KiB range from existing Stage2 material:
864 KiB allocated total. No additional expander output or per-block material.
Validation independently checks exported ranges, global single/complement
exclusions, each eight-value job's 256 distinct subset sums, actual free-byte
subset sums, and the odd-offset constraint. Combination exclusions are local
to each job; there is no cross-job subset-sum guarantee.

Old rotation packs, selection statistics and superseded rotation buffers are
removed from the active composer. Obsolete source remains in Dead Code.
A failed farm clears readiness and prevents stale-vault encryption.
The rotation migration changes generated plans/ciphertext for the same seed.
The subsequent cipher cleanup does not alter the retained cipher algorithms.
